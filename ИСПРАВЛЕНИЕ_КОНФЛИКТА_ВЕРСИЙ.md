# Исправление конфликта версий при сохранении в GitHub

## Проблема

При сохранении данных в GitHub возникала ошибка:
```
Ошибка: Конфликт версий. Файл был изменён. Попробуйте ещё раз.
Данные сохранены локально.
```

Эта ошибка (HTTP 409) возникала, когда файл `data.json` на GitHub был изменён между моментом получения его SHA и отправкой PUT запроса на обновление.

## Причина

GitHub API требует, чтобы при обновлении файла вы указывали его текущий SHA. Если SHA не совпадает с актуальным (файл был изменён другим процессом), GitHub возвращает ошибку 409 Conflict.

Это может происходить, когда:
- Несколько устройств одновременно сохраняют данные
- Файл был изменён вручную через веб-интерфейс GitHub
- Другой процесс обновил файл

## Решение

Добавлен механизм повторных попыток с получением актуального SHA файла:

### Алгоритм работы:

1. **Попытка 1:**
   - Получаем актуальный SHA файла
   - Формируем данные для сохранения
   - Отправляем PUT запрос
   - Если успех → завершаем
   - Если конфликт (409) → переходим к попытке 2

2. **Попытка 2:**
   - Ждём 1 секунду
   - Получаем НОВЫЙ актуальный SHA файла
   - Формируем данные для сохранения
   - Отправляем PUT запрос
   - Если успех → завершаем
   - Если конфликт (409) → переходим к попытке 3

3. **Попытка 3:**
   - Ждём 1 секунду
   - Получаем НОВЫЙ актуальный SHA файла
   - Формируем данные для сохранения
   - Отправляем PUT запрос
   - Если успех → завершаем
   - Если конфликт (409) → выбрасываем ошибку

```javascript
        });

            return true;
        }
        
        if (response.status === 409) {
            console.warn(`⚠️ Конфликт версий (попытка ${attempt}/${maxRetries})`);
            if (attempt < maxRetries) {
                console.log('⏳ Ожидание перед повторной попыткой...');
                await new Promise(resolve => setTimeout(resolve, 1000));

        console.error(`❌ Ошибка при попытке ${attempt}:`, error.message);
        
        if (attempt < maxRetries) {
            console.log('⏳ Ожидание перед повторной попыткой...');
            await new Promise(resolve => setTimeout(resolve, 1000));
        }
    }
}

throw lastError || new Error('Не удалось сохранить данные после нескольких попыток');
```

## Преимущества решения

1. **Автоматическое восстановление**: Система сама повторяет попытку при конфликте
2. **Актуальные данные**: Каждая попытка получает свежий SHA файла
3. **Защита от гонок**: Задержка между попытками снижает вероятность повторного конфликта
4. **Информативность**: Подробное логирование помогает диагностировать проблемы
5. **Надёжность**: 3 попытки значительно повышают шанс успешного сохранения

## Рекомендации

1. **Избегайте одновременного сохранения**: Если несколько преподавателей работают с системой, договоритесь о порядке сохранения
2. **Проверяйте консоль браузера**: Логи помогут понять, что происходит при сохранении
3. **Используйте синхронизацию**: Перед началом работы нажмите "🔄 Синхронизация", чтобы загрузить актуальные данные
4. **Сохраняйте регулярно**: Не накапливайте много изменений, сохраняйте чаще

## Технические детали

- **Максимум попыток**: 3
- **Задержка между попытками**: 1 секунда
- **Общее время ожидания**: до 3 секунд
- **Кэширование**: отключено (`cache: 'no-store'`)
- **Защита от параллельных сохранений**: флаг `isSaving`
