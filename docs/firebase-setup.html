🔥 Инструкция по настройке Firebase

⚠️ Важно: Без настройки Firebase изменения, внесённые на одном устройстве, не будут видны на других устройствах. Эта инструкция займёт всего 10 минут.

Зачем нужен Firebase?

Сейчас данные сохраняются только в браузере конкретного устройства (localStorage). Когда преподаватель вносит изменения на своём компьютере, студенты на других устройствах их не видят.

Firebase решает эту проблему — все данные синхронизируются в облаке в реальном времени.

1 Создание проекта Firebase (2 минуты)
  1. Перейдите на console.firebase.google.com
  2. Войдите в свой Google аккаунт
  3. Нажмите "Добавить проект"
  4. Введите название: rating-system
  5. Отключите Google Analytics (не обязательно)
  6. Нажмите "Создать проект"
2 Создание Realtime Database (2 минуты)
  1. В левом меню нажмите "Realtime Database"
  2. Нажмите "Создать базу данных"
  3. Выберите регион: europe-west1
  4. Выберите "Начать в тестовом режиме"
  5. Нажмите "Включить"
3 Получение конфигурации (2 минуты)
  1. Нажмите на шестерёнку ⚙️ в левом верхнем углу
  2. Выберите "Настройки проекта"
  3. Прокрутите вниз до раздела "Ваши приложения"
  4. Нажмите на иконку веб-приложения </>
  5. Введите название: rating-web
  6. Нажмите "Зарегистрировать приложение"
  7. Скопируйте объект firebaseConfig:
const firebaseConfig = { apiKey: "AIzaSy...", authDomain: "rating-system.firebaseapp.com", databaseURL: "https://rating-system-default-rtdb.europe-west1.firebasedatabase.app", projectId: "rating-system", storageBucket: "rating-system.appspot.com", messagingSenderId: "123456789", appId: "1:123456789:web:abc123..." };
4 Вставка конфигурации в код (1 минута)
  1. Откройте файл docs/index.html в текстовом редакторе
  2. Найдите строку с комментарием: // ВСТАВЬТЕ СЮДА ВАШУ КОНФИГУРАЦИЮ FIREBASE
  3. Замените плейсхолдеры на ваши значения из firebaseConfig
  4. Сохраните файл
Важно: Убедитесь, что все поля заполнены correctly. Не оставляйте YOUR_API_KEY или другие плейсхолдеры!
5 Публикация изменений (1 минута) 
git add docs/index.html
git commit -m "Добавлена интеграция с Firebase"
git push

GitHub Pages автоматически пересоберёт сайт через 1-2 минуты.

6 Проверка работы (2 минуты)
  1. Откройте сайт на первом устройстве (компьютер преподавателя)
  2. Откройте консоль браузера (F12 → вкладка Console)
  3. Вы должны увидеть: ✅ Firebase инициализирован
  4. Войдите как преподаватель (пароль: 05072020)
  5. Внесите изменения (добавьте курсанта или измените баллы)
  6. Нажмите "💾 Сохранить"
  7. Откройте сайт на втором устройстве (телефон студента)
  8. Обновите страницу (F5)
  9. ✨ Изменения должны появиться автоматически!

Как это работает?

🔄 Синхронизация в реальном времени:
  1. Преподаватель вносит изменения → данные сохраняются в Firebase
  2. Firebase уведомляет все подключённые устройства об изменениях
  3. Все устройства автоматически обновляют данные

Устранение проблем

Проблема: "Firebase не инициализирован" в консоли
Решение: Проверьте, что вы правильно скопировали firebaseConfig. Убедитесь, что все поля заполнены.
Проблема: Данные не синхронизируются между устройствами
Решение:
  • Убедитесь, что на обоих устройствах используется одна и та же конфигурация Firebase
  • Проверьте консоль браузера на обоих устройствах
  • Обновите страницу (F5) на обоих устройствах
Проблема: Старые данные из localStorage перезаписывают новые из Firebase
Решение: Очистите localStorage: 
// В консоли браузера (F12):
localStorage.clear();
// Затем обновите страницу (F5)

Стоимость

Бесплатный тариф Spark:
  • 1 ГБ хранилища
  • 10 ГБ передачи данных в месяц
  • 100 одновременных подключений
Для небольшого количества курсантов (до 100-200 человек) этого более чем достаточно.

Безопасность

Сейчас база данных работает в тестовом режиме — любой, кто знает URL, может читать и писать данные.

Для продакшена рекомендуется настроить правила безопасности в Firebase Console:

  1. Перейдите в Realtime Database → вкладка "Правила"
  2. Замените правила на:
{
  "rules": {
    ".read": true,
    ".write": "auth != null"
  }
}

Это разрешит чтение всем, но запись только авторизованным пользователям.
