# ✅ Исправлена ошибка HTTP 409 при сохранении в GitHub

## 🐛 Проблема

При сохранении данных в GitHub возникала ошибка:
```
HTTP 409: data.json does not match 589ff3463e21710bc5725f46e44c965c3e2c1772
```

### Причина ошибки

Ошибка 409 (Conflict) возникает, когда:
1. Мы получаем SHA файла из GitHub
2. Пока мы готовим данные для отправки, файл на GitHub изменяется
3. При отправке PUT запроса GitHub видит, что SHA не совпадает с текущим
4. GitHub возвращает ошибку 409 Conflict

Это классическая проблема при работе с GitHub API - состояние гонки (race condition).

---

## 🔧 Решение

### Что было исправлено

Функция `writeToGitHub()` в `docs/index.html` была полностью переработана:

**Было:**
- Одна попытка записи
- При ошибке 409 - сразу ошибка

**Стало:**
- Механизм повторных попыток (retry)
- Максимум 3 попытки
- Автоматическое получение нового SHA при конфликте
- Задержка 1 секунда между попытками

### Как это работает

```javascript
// Повторные попытки при конфликте (максимум 3)
const maxRetries = 3;

for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
        // 1. Получаем актуальный SHA файла
        const getResponse = await fetch(url, {...});
        
        // 2. Формируем запрос с новым SHA
        const requestBody = {
            message: 'Обновление данных рейтинга курсантов',
            content: content,
            branch: GITHUB_CONFIG.branch,
            sha: sha  // Актуальный SHA
        };
        
        // 3. Отправляем запрос
        const response = await fetch(url, {...});
        
        if (response.ok) {
            return true;  // Успех!
        }
        
        if (response.status === 409) {
            // Конфликт - пробуем снова
            console.warn(`⚠️ Конфликт (409): файл был изменён. Повторная попытка...`);
            await new Promise(resolve => setTimeout(resolve, 1000));
            continue;
        }
        
    } catch (error) {
        if (attempt === maxRetries) {
            throw error;  // Все попытки исчерпаны
        }
        await new Promise(resolve => setTimeout(resolve, 1000));
    }
}
```

## 🎯 Преимущества нового решения

### 1. Автоматическое восстановление
- Не нужно вручную повторять сохранение
- Система сама пытается исправить проблему

### 2. Устойчивость к конфликтам
- Работает даже если файл часто изменяется
- Подходит для совместной работы

### 3. Подробное логирование
- В консоли видно все попытки
- Легко диагностировать проблемы

### 4. Ограниченное количество попыток
- Максимум 3 попытки
- Не бесконечный цикл
- Быстрая обратная связь при реальной ошибке

## 📝 Что делать если ошибка всё ещё возникает

### Если все 3 попытки не удались:

1. **Проверьте, не редактирует ли кто-то файл одновременно**
   - Откройте репозиторий на GitHub
   - Проверьте историю коммитов
   - Убедитесь, что нет параллельных изменений

2. **Подождите и попробуйте снова**
   - Возможно, файл блокируется другим процессом
   - Подождите 10-20 секунд
   - Попробуйте сохранить снова

3. **Очистите localStorage**
   ```javascript
   localStorage.clear();
   location.reload();
   ```

4. **Проверьте настройки GitHub**
   - Владелец репозитория
   - Название репозитория
   - Токен (права repo)
   - Путь к файлу
