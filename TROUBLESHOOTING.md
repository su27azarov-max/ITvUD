# Устранение проблем с синхронизацией GitHub

## Частые ошибки и их решения

### Ошибка 1: "Неверный токен GitHub"

**Причина:** Токен недействителен, истёк или введён неправильно.

**Решение:**
1. Проверьте, что токен начинается с `ghp_` или `github_pat_`
2. Убедитесь, что скопировали весь токен без пробелов
3. Проверьте срок действия токена на https://github.com/settings/tokens
4. Если токен истёк - создайте новый

**Как проверить:**
- Откройте консоль браузера (F12)
- Нажмите "⚙️ GitHub" → "🔍 Тест"
- Посмотрите ошибки в консоли

---

### Ошибка 2: "Доступ запрещён. Проверьте права токена"

**Причина:** Токен не имеет необходимых прав для работы с репозиторием.

**Решение:**
1. Перейдите на https://github.com/settings/tokens
2. Нажмите на ваш токен
3. Убедитесь, что отмечен чекбокс **`repo`** (полный доступ к репозиториям)
4. Если нет - создайте новый токен с правильными правами

**Важно:** Для тонкой настройки можно использовать Fine-grained token:
1. Выберите "Fine-grained token"
2. Укажите только нужный репозиторий
3. Дайте права: **Contents** → Read and write

---

### Ошибка 3: "Репозиторий не найден"

**Причина:** Неправильно указано имя владельца или репозитория.

**Решение:**
1. Проверьте имя владельца (username или organization)
   - Должно быть точно как в URL: `github.com/USERNAME`
   - Пример: если URL `github.com/ivanov/rating-system`, то владелец = `ivanov`

2. Проверьте имя репозитория
   - Должно быть точно как в URL
   - Пример: если URL `github.com/ivanov/rating-system`, то репозиторий = `rating-system`

3. Убедитесь, что репозиторий **публичный**
   - Откройте репозиторий
   - Перейдите в Settings
   - Прокрутите вниз до "Danger Zone"
   - Проверьте, что репозиторий Public

---

### Ошибка 4: "Файл data.json не найден"

**Причина:** Файл `data.json` не существует в репозитории.

**Решение:**
1. Откройте репозиторий на GitHub
2. Нажмите "Add file" → "Create new file"
3. Введите имя: `data.json`
4. Скопируйте содержимое из файла `data.json` в корне этого проекта
5. Нажмите "Commit new file"

**Или:**
- Нажмите "💾 Сохранить" в приложении - файл создастся автоматически

---

### Ошибка 5: CORS ошибка в консоли

**Причина:** GitHub API блокирует некоторые запросы из-за политики CORS.

**Решение:**
1. Убедитесь, что используете HTTPS (GitHub Pages автоматически использует HTTPS)
2. Очистите кэш браузера (Ctrl+Shift+Delete)
3. Попробуйте другой браузер
4. Проверьте, что токен действителен

**Если проблема сохраняется:**
- GitHub API должен поддерживать CORS для авторизованных запросов
- Если ошибка продолжает появляться, возможно проблема с сетью или провайдером

---

### Ошибка 6: "Ошибка валидации"

**Причина:** Неправильный формат данных или SHA файла.

**Решение:**
1. Очистите localStorage:
   ```javascript
   // В консоли браузера (F12):
   localStorage.clear();
   ```
2. Обновите страницу (F5)
3. Попробуйте сохранить снова

---

### Ошибка 7: Данные не синхронизируются между устройствами

**Причина:** Данные не сохраняются в GitHub или не загружаются на другом устройстве.

**Решение:**
1. На первом устройстве:
   - Внесите изменения
   - Нажмите "💾 Сохранить"
   - Дождитесь сообщения "✅ Изменения сохранены в GitHub"
   - Проверьте на GitHub, что файл `data.json` обновился

2. На втором устройстве:
   - Откройте сайт
   - Нажмите "🔄 Синхронизация"
   - Или обновите страницу (F5)
   - Проверьте консоль (F12) на наличие ошибок

## Диагностика проблем

### Шаг 1: Проверьте консоль браузера

1. Откройте сайт
2. Нажмите F12 (или Ctrl+Shift+I)
3. Перейдите на вкладку "Console"
4. Посмотрите на сообщения:
   - ✅ Зелёные - всё хорошо
   - ⚠️ Жёлтые - предупреждения
   - ❌ Красные - ошибки

### Шаг 2: Проверьте настройки GitHub

1. Войдите как преподаватель
2. Нажмите "⚙️ GitHub"
3. Проверьте все поля:
   - Владелец: без пробелов, точно как на GitHub
   - Репозиторий: без пробелов, точно как на GitHub
   - Token: начинается с `ghp_` или `github_pat_`
   - Путь: `data.json`
   - Ветка: `main`

### Шаг 3: Протестируйте соединение

1. Нажмите "🔍 Тест" в окне настроек GitHub
2. Посмотрите результат:
   - ✅ "Соединение с GitHub работает!" - всё хорошо
   - ❌ Ошибка - следуйте инструкциям в сообщении

### Шаг 4: Проверьте файл на GitHub

1. Откройте репозиторий на GitHub
2. Найдите файл `data.json`
3. Проверьте:
   - Файл существует
   - Содержимое валидный JSON
   - Последнее обновление недавнее

## Альтернативные решения

Если GitHub API продолжает работать с ошибками, рассмотрите альтернативы:

### 1. Ручной экспорт/импорт
- Используйте "💾 Экспорт" для сохранения данных в файл
- Используйте "📂 Загрузить" для импорта на другом устройстве
- **Плюсы:** Просто, работает всегда
- **Минусы:** Требует ручных действий

### 2. Firebase Realtime Database
- Синхронизация в реальном времени
- Бесплатный тариф: 1 ГБ хранилища
- Инструкция: `FIREBASE_SETUP.md`
- **Плюсы:** Автоматическая синхронизация
- **Минусы:** Может быть медленным из России

### 3. Локальное хранение
- Используйте только localStorage
- Данные сохраняются только на одном устройстве
- **Плюсы:** Просто, быстро
- **Минусы:** Нет синхронизации между устройствами

## Получение помощи

Если проблема не решена:

1. **Соберите информацию:**
   - Скриншот ошибки
   - Скриншот настроек GitHub (скройте токен!)
   - Содержимое консоли браузера (F12)
   - URL репозитория на GitHub

2. **Проверьте:**
   - Токен действителен и имеет права `repo`
   - Репозиторий публичный
   - Файл `data.json` существует
   - Имя владельца и репозитория правильные

3. **Попробуйте:**
   - Очистить localStorage
   - Обновить страницу
   - Использовать другой браузер
   - Проверить интернет-соединение

## Быстрая проверка

Запустите эту команду в консоли браузера (F12) для быстрой проверки:

```javascript
// Проверка конфигурации
const config = JSON.parse(localStorage.getItem('github_config'));
console.log('Конфигурация GitHub:', config);

// Проверка токена
if (config && config.token) {
    console.log('Токен начинается с:', config.token.substring(0, 10) + '...');
    console.log('Длина токена:', config.token.length);
} else {
    console.log('GitHub не настроен');
}
```

---

**Помните:** GitHub API имеет лимит 5000 запросов в час для авторизованных пользователей. Этого более чем достаточно для обычного использования.
